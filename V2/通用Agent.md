# 通用 Agent 规则

## 1. 核心行为准则
- **语言**：始终使用**中文**与用户对话。
- **一致性**：文档与代码实现必须保持严格一致。修改代码后，必须同步更新相关文档。
- **确认优先 (关键)**：
    - **拒绝“直接开干”**：**禁止直接开始写代码**。
    - **执行协议**：
        1.  **理解**：先复述你对任务的理解。
        2.  **实现方案**：给出具体的实现方案。
        3.  **确认**：获得用户批准后方可执行。
    - *例外*：仅针对显而易见的简单修正（如“修复拼写错误”）可直接执行。

## 2. 开发规范

### 2.1 全局上下文感知 (Context Awareness)
在开始任何开发任务前，**必须主动扫描并阅读**项目的核心文档和现有代码结构。这是 AI 准确理解项目上下文、避免“幻觉”代码的前提。只有建立在对项目全面理解的基础上，才能产出高质量代码。

### 2.2 代码复用原则 (DRY Principle)
严禁重复造轮子。在编写新代码前，**必须先检索**项目中是否存在已有的工具函数、组件或模块。优先复用现有逻辑，保持代码库的简洁与一致性。

### 2.3 开发与维护 (Dev & Ops)
- **BUG 修复标准**：执行修复任务时，必须调用 `bugfix-workflow `Skill。严格遵循“复现 -> 定位 -> 修复 -> 验证”的闭环流程，并生成标准化的 BUG 修复报告。 

## 3. 文档同步策略
- **修改必查**：每次修改代码时，检查是否影响了相关文档，如影响了请进行同步更新。
- **级联更新**：如果修改了上游文档，必须检查下游文档是否需要同步调整。
- **文档优先**：对于新功能的开发，推荐遵循“文档驱动开发”模式，先更新文档，再写代码。

## 4. MCP 工具使用规范

### 4.1 知识库查询 (Context7)
在涉及技术实现、API 调用或框架使用时，**禁止仅依赖训练数据**。
- **强制要求**：**必须**调用 `Context7` MCP 工具查询相关库/框架的最新官方文档。
- **目的**：确保代码符合当前版本的最佳实践，避免使用过时或被废弃的 API。
