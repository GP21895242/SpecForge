# AI 工作流 V2

> V2 核心理念：**文档驱动开发，前端先行**。
> 每一步产出明确文档，功能阶段边写需求边完成前端，实现"所见即所得"的开发体验。

---

## 工作流总览

```
需求挖掘 → 项目定义 → 技术选型 → 架构设计 → 规范制定 → 功能开发（文档 + 前端同步推进）
```

| 阶段 | 目标 | 产出文档 |
| :--- | :--- | :--- |
| **01 需求挖掘** | 把模糊想法变成清晰描述 | 对话记录 / 需求摘要 |
| **02 项目定义** | 确定产品愿景、核心价值、目标用户 | `specs/1_产品概述.md` |
| **03 技术选型** | 选定技术栈，给出选型理由 | `specs/2_技术栈.md` |
| **04 架构设计** | 定义目录结构与模块划分 | `specs/3_项目结构.md` |
| **05 规范制定** | 统一代码风格、命名、提交规范 | `specs/4_开发规范.md` |
| **06 功能开发** | 逐个功能：编写需求文档，同步完成前端开发 | `docs/{功能名}/` |

### 关于阶段 06 — 文档与前端同步推进

这是 V2 与 V1 的最大区别：

- **V1**：先写完全部文档（需求 → UI 原型 → 技术方案 → 任务规划），再进入编码。
- **V2**：在编写功能说明文档的同时，直接完成前端页面开发。先把前端全部做完，再对接后端逻辑。

这样做的好处：
1. **所见即所得** — 写需求时就能看到真实界面，减少理解偏差。
2. **前端先行** — 所有页面和交互提前落地，后端可以按接口契约并行开发。
3. **减少文档浪费** — 不再产出大量中间文档，文档和代码同步演进。
