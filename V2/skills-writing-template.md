# Skill 介绍文章写作模板

每个 Skill 的介绍遵循以下四部分结构：**为什么 → 怎么做 → 输出什么 → 长什么样**。

---

## 1. 痛点场景（为什么需要这个 Skill）

描述"如果没有这个 Skill，你会遇到什么问题"，用具体场景让读者产生共鸣。

**写法要点：**
- 从读者的真实行为切入（"大多数人的做法是..."、"你可能会直接..."）
- 描述具体后果，不要泛泛而谈（"写到一半发现..."、"改起来比重写还痛苦"）
- 一两段即可，不要铺太长

**示例参考：**
- 技术栈选型：追热门框架踩坑、全交给 AI 选结果用不起来
- 开发规范：十个文件十种代码风格，改起来比提前定好更痛苦
- BUG 修复：丢个报错给 AI，它猜个原因改了，旧 BUG 没了新 BUG 来了

---

## 2. 解决方案（这个 Skill 怎么做的）

说明三件事：AI 扮演什么角色、核心做了什么、最厉害的设计点在哪。

**写法要点：**
- 先说 AI 角色（"扮演的是**产品经理**"、"角色是**CTO**"）
- 用一两句话概括核心能力，不要罗列所有功能
- 突出一个最打动人的设计点（"最厉害的地方在于..."、"最贴心的设计是..."）
- 口语化表达，避免说明书语气

**示例参考：**
- 需求澄清：像"好奇的合伙人"在聊天，不是填表机器
- 项目初始化：唯一的执行类 Skill，严格按文档创建骨架，不自作主张
- 功能迭代：自动分类变更类型（微调/扩展/重构），增量更新不推倒重写

---

## 3. 产出物（输出什么）

一句话说明最终生成什么文件、存到哪个路径。

**写法要点：**
- 简洁，一句话搞定
- 用内联代码格式标注路径（如 `specs/产品概述.md`）
- 如果产出物较多可以用短列表

---

## 4. 使用示例（用户发什么 → AI 怎么回复）

一个完整的交互示例，体现该 Skill 的核心交互特点。

**写法要点：**
- 用户输入用内联代码格式：`` `/skill-name 具体指令` ``
- AI 回复用引用块格式（`>`），模拟真实对话感
- 回复内容要体现该 Skill 的核心特点：

| Skill 类型 | 示例中 AI 回复应体现的特点 |
|------------|--------------------------|
| 需求类 | 给选项 + 给推荐 + 一次只问 1-2 个问题 |
| 设计类 | 列出多种方案的优劣对比 + 推荐一个 |
| 规划类 | 任务清单 + 依赖关系 + 工时估算 |
| 执行类 | 检查清单 + 执行过程 + 完成状态 |
| BUG 修复 | 先追问复现信息，拒绝直接改代码 |

- 示例不要太长，展示一轮交互即可，让读者能快速理解"用起来是什么感觉"

---

## 整体原则

- **前后连贯**：所有示例围绕同一个项目（如"个人博客"），让读者看到完整链条
- **口语化**：像跟朋友聊天，不是写技术文档
- **不重复**：每个 Skill 只突出自己独特的价值，跟前一个 Skill 重叠的部分不再赘述
- **Skill 之间用 `---` 分隔**，标题格式统一为 `## Skill N：skill-name（中文名）`
