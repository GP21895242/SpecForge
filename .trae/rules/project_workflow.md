# 项目级工作流规范 (Project-Level Workflow)

## 1. 概述
本规范旨在定义“全局层”的项目启动与维护流程，确保项目从零到一的构建过程结构清晰、标准统一，并具备持续优化的能力。该流程为后续的“功能级工作流”提供坚实的基础设施和规则指导。

## 2. 核心流程

我们采用以下五个阶段的标准化流程来构建和维护项目全局上下文：

### 阶段一：需求挖掘 (Requirements Elicitation)
**目标**：将模糊的想法转化为清晰的项目描述，作为项目定义的输入。
*   **输入**：原始想法 (Idea)。
*   **动作**：
    *   使用 `0_需求澄清.md` (Meta-Prompt) 进行苏格拉底式提问。
    *   挖掘核心价值、目标用户、关键特性。
*   **产出**：标准化项目描述文本（非独立文档，直接用于下一阶段）。

### 阶段二：项目定义 (Project Definition)
**目标**：明确项目的核心价值与愿景。
*   **输入**：标准化项目描述。
*   **动作**：
    *   使用 `1_产品概述.md` 生成正式文档。
    *   明确项目背景与痛点。
    *   定义核心功能模块。
    *   确定用户群体。
*   **产出**：`1_产品概述.md` (Product Overview)

### 阶段三：技术选型与架构 (Tech Stack & Architecture)
**目标**：确立项目的技术地基。
*   **动作**：
    *   **技术栈选择**：使用 `2_技术栈.md` 进行前端、后端、数据库及工具链选型。
    *   **架构规划**：使用 `3_项目结构.md` 定义目录结构、模块划分原则。
*   **产出**：
    *   `2_技术栈.md` (Tech Stack)
    *   `3_项目结构.md` (Project Structure)

### 阶段四：规范制定 (Standardization)
**目标**：统一团队协作语言，降低沟通成本。
*   **动作**：
    *   使用 `4_开发规范.md` 制定代码风格 (Linting/Formatting)。
    *   约定 Git 提交规范。
    *   定义命名约定 (文件、变量、接口)。
*   **产出**：`4_开发规范.md` (Dev Standards)

### 阶段五：复盘与进化 (Review & Evolution)
**目标**：构建“反脆弱”系统，防止重复错误。
*   **动作**：
    *   使用 `5_AI错题本.md` 记录 AI 在开发过程中犯过的典型错误。
    *   总结最佳实践与坑点。
    *   定期更新上述文档。
*   **产出**：`5_AI错题本.md` (AI Mistakes)

---
## 3. 文档管理约定
所有全局层文档统一存储于 `.trae/rules/` 目录下，作为项目最重要的全局上下文 (Global Context)。
